# 1. 核心协议与通信层（不可变契约）

## 1.1 三层拓扑

```
┌────────────────────┐        ┌─────────────────────┐        ┌──────────────────┐
│  前端组件           │  1 次  │  本地代理            │  3 次  │  大模型平台       │
│  sendMessageToX()  │───────▶│  127.0.0.1:8787     │───────▶│  api.coze.cn     │
│                    │◀───────│  零依赖 Node         │◀───────│  /v3/chat        │
└────────────────────┘  纯文本 └─────────────────────┘  轮询   └──────────────────┘
     无密钥                     唯一持密钥者              唯一出网者
```

这个形状由两个**独立**的问题逼出来，两者都不能靠「前端直接调 API」解决：

| 问题 | 后果 | 解法 |
|---|---|---|
| 平台不给浏览器发 CORS 头 | 直连 fetch 必失败，`file://` 下源是 `null` 更没戏 | 代理回 `Access-Control-Allow-Origin: *` |
| PAT 若进前端 = 公开给所有访问者 | 额度被盗用、无法吊销单个用户 | 凭证只进代理进程 |

**不要用 Next API 路由替代独立代理进程**——静态导出（`output: "export"`）没有服务端，单文件 `file://` 版本会整条链路失效。独立进程能同时服务 dev 站点和 `file://` 双击两种形态，这是它存在的核心理由。

## 1.2 前后端契约（代理的公开面）

这是前端唯一需要知道的接口，**换学科、换模型平台都不应改变它**。

```
POST http://127.0.0.1:8787/chat
Content-Type: application/json

{ "text": "用户问题", "conversationId": "可选，续接用" }

→ 200 { "ok": true,  "reply": "纯文本（含协议链接）", "conversationId": "..." }
→ 502 { "ok": false, "kind": "coze", "error": "可直接展示的中文句子" }

GET  http://127.0.0.1:8787/health
→ 200 { "ok": true, "mock": false, "hasPat": true, "hasBotId": true }
```

三条设计约定：

1. **`reply` 是纯文本，不是 JSON 结构体**。协议链接以 markdown 形态嵌在文本里，由前端解析器负责拆。这让代理保持「哑管道」，任何模型平台只要能出文本就能接。
2. **`error` 是给用户看的话，不是给日志看的堆栈**。前端直接把它渲染进气泡，不做二次翻译。`kind` 只用于决定要不要重试按钮。
3. **`/health` 只返回布尔值，绝不回显密钥**。它同时充当「代理活没活」的探针，供总览页显示状态灯。

## 1.3 代理内部封装了什么

非流式对话接口通常**不会在创建响应里返回正文**。以扣子 v3 为例，真实链路是三段：

```
POST /v3/chat            → 只拿到 { id, conversation_id, status: "in_progress" }
GET  /v3/chat/retrieve   → 轮询到 status === "completed"（实测约 15–17 秒）
GET  /v3/chat/message/list → 拿正文
```

**这三段必须全部藏在代理里。** 前端只发一次请求、只等一个结果，否则超时控制、重试、轮询状态机会散落到每个调用点。

### ⚠️ 实测踩坑：不要凭文档假设响应结构

本项目最初按「`message.content` 是 `[{type:"text",text:…}]` 的 JSON 字符串，且消息带 `status` 字段」实现，结果线上**恒定返回空正文**。真实结构是：

- `answer` 消息的 `content` 是**纯文本**，不是 JSON 数组
- 消息对象上**根本没有 `status` 字段**，用它做过滤条件会把所有消息滤光
- 同一批消息里混着 `function_call` / `tool_response` / `verbose` / `follow_up`，必须按 `type === "answer"` 挑

**可迁移的教训**：接任何外部模型平台，第一步永远是**把原始响应 dump 出来看**，不要照 API 文档写解析器。文档说的和线上返回的不一致是常态。

因此解析器要做成**双形态兼容**：`content` 能 `JSON.parse` 成数组就按分段取文本，否则整串当纯文本用。

## 1.4 错误分类

固定这套 `kind`，前端只需一张映射表：

| kind | 含义 | 前端呈现 | 可重试 |
|---|---|---|---|
| `network` | 代理连不上模型平台 | 检查本机网络 | 是 |
| `config` | 凭证缺失/无效、入参非法 | 提示改 `.env.local` | 否 |
| `rate` | 平台限流（429） | 稍后再试 | 是 |
| `timeout` | 轮询超上限（默认 60s） | 把问题问短一点 | 是 |
| `empty` | 跑完了但没正文 | 换一种问法 | 是 |
| `coze`/`provider` | 平台侧业务错误 | 原样展示 | 视情况 |

超时预算要**分层且留余量**：代理轮询 60s < 前端 fetch 90s。反过来会让前端先 abort，拿不到代理已经查到的真实错误。

## 1.5 凭证边界

```
.env.local          ← 唯一存放处，.gitignore 已含 .env*
   ├─ <PROVIDER>_PAT
   └─ <PROVIDER>_BOT_ID

代理进程读取          ← 唯一读者
前端 coze-config.ts  ← 只有代理地址，NEXT_PUBLIC_* 前缀，非机密
```

用内置的十几行 `.env` 解析器，**不要用 `node --env-file`**：文件不存在时该 flag 会硬失败，而 `--env-file-if-exists` 需要 Node 22+，与 `engines: >=20.9` 冲突。

落地后必须做的两道自查：`grep -rl "<PAT片段>" .` 应只命中 `.env.local`；构建产物目录里再 grep 一次，确认没被内联进客户端包。

## 1.6 AI 输出协议规范（硬契约）

协议是**前端与云端提示词之间的接口**。换学科时前端不改，云端提示词里的编号集合要换。

```
[任意标签文字](kb://<正整数>)        知识点跳转
[任意标签文字](exp://<实验编号>)      实验页跳转
```

| 项 | 规定 | 理由 |
|---|---|---|
| 协议名 | `kb` / `exp`，大小写不敏感 | 模型会写 `KB://` |
| 括号 | 半角 `()` 与全角 `（）` 都接受 | 中文模型输出全角是高频行为 |
| 方括号 | 半角 `[]` 与全角 `【】` 都接受 | 同上 |
| 空白 | `://` 两侧、括号内侧允许空格 | 模型会插入排版空格 |
| 标签内容 | 不得跨行 | 否则一段正文会被误吞成一个链接 |
| `kb` 参数 | 纯数字，语义是**目录页码/条目序号**，不是数组下标 | 见 §1.8 |
| `exp` 参数 | 带字母前缀的编号，**必须来自封闭集合** | 见 §1.7 第 5 条 |
| 一条消息 | 允许任意多个协议，可位于首/尾/相邻 | 实测会连写 |

**协议必须写在提示词里、且给出正反例**，否则模型会自己发明 `教材://` 或 `[P.373](373)` 这类变体。附录 §4.2 给了可直接粘贴的约束模板。

## 1.7 解析器的五条不变式

函数签名刻意**不返回 HTML 字符串**：

```ts
parseMessageSegments(raw: string): MessageSegment[]

type MessageSegment =
  | { type: "text"; text: string }
  | { type: "kb";   page: number; label: string }
  | { type: "exp";  id: string; code: string; label: string }
```

1. **绝不产出 HTML 字符串，绝不用 `innerHTML` / `dangerouslySetInnerHTML`。** 模型输出是不可信输入，拼 HTML 等于开一条 XSS 通道（一次 `onerror` 就能把代理地址和会话内容带出去）。返回类型化片段、由框架渲染真实节点，转义是白送的。
2. **不匹配任何协议的内容 100% 原样保留为 text 片段**，包括未闭合的 `](kb://` 残片。解析器不许吞字符——用户会以为答案被截断了。
3. **换行交给 CSS**（`white-space: pre-wrap`），不拆 `<br>`。既省一次字符串手术，也让复制粘贴出来的文本是干净的。
4. **模块级 `g` 正则必须在入口复位 `lastIndex`**，否则第二次调用会从上次匹配位置继续，表现为「同样的文本，第二次解析结果不一样」。这是极难复现的一类 bug。
5. **无法校验的编号降级为纯文本，不生成链接。** `exp://E10` 若集合里没有，就只显示「E10 对应的标签文字」。宁可少一个按钮，也不要一个点开 404 的按钮——404 会让用户怀疑整个系统。

## 1.8 两套 ID 解析原则（换学科必须重新推导，但原则不变）

协议里的数字要落到具体条目，需要两套反向索引。这两套的**算法选型是反直觉的**，是本项目最容易踩错的地方。

### A. 页码 → 条目：用「覆盖区间」，不要用「最近邻」

条目稀疏（169 条覆盖 614 页），必然存在没有归属的页码。

```
1. 先按章的页码范围（如 "359-376"）定位所属章
2. 章内按页升序，取【最后一个 page <= 目标页】的条目
3. 若目标页早于该章首条，取该章首条
4. 若不属于任何章 → 返回 null，前端就地提示，不静默跳错
```

**为什么不能用最近页**：目标页 373，最近的是 374（下一节），但 373 实际属于 371 那一节的延续区间。覆盖区间给的是语义正确的条目，最近邻给的是错的。

### B. 条目 → 实验：用「编号匹配」，不要用「页码相等」

从条目标题和实验的章节标注里各抽出小节号（正则 `\d+\.\d+`，多段标注先按 ` · ` 拆分），有交集即关联。

**为什么不能用页码相等**，两个方向都会错：

- **漏**：有的实验页码落在两条目之间，任何条目都没有这个页码 → 该实验永远挂不上去
- **误报**：同页可能有多个条目，会把无关条目也标上按钮

用编号匹配后，本项目 169 条里恰好命中 10 条，且同页的无关条目被正确排除。

### ⚠️ 已知缺口：`kb://` 缺白名单校验

`exp://` 有封闭集合校验，`kb://` **没有**——任何落在某章范围内的页码都会被解析出一个真实存在的条目，于是**一个错误的页码会跳到一个「看起来完全正常」的地方**。实测模型答 P.127（正确应为 P.371-373），前端不报错、正常跳转，只有人眼能发现错。

换学科时应补上这道校验，三选一：

1. 提示词里给出**合法页码的封闭清单**，并要求只能引用清单内的值（成本最低）
2. 前端维护「合法页码集合」，不在集合内则降级为纯文本（与 `exp://` 对齐，最一致）
3. 代理侧出正文后做一次校验与改写（能同时修错，但需要维护映射表）

## 1.9 多轮上下文

协议上支持传 `conversationId` 续接会话，但**是否真的生效取决于平台侧的「上下文/记忆」开关**。本项目实测该 bot 忽略传入的 `conversation_id`、每次新建会话。

架构上保持「传了就用、不传就新开会话」的惰性实现即可，不要为此加前端复杂度。**但不要在 UI 上把「多轮记忆」当卖点宣传**，除非已在平台侧验证通过。

# 2. UI 组件与交互解耦

## 2.1 AI 悬浮窗：契约面 vs 皮肤面

组件对外只有三个 props，这就是它的全部接缝：

```ts
type AssistantDockProps = {
  open: boolean;
  onOpenChange: (open: boolean) => void;
  onJumpToKnowledge: (target: KnowledgeTarget) => void;
};
```

换 UI 时按下表切分：

| 属于契约（**保留**） | 属于皮肤（**随便换**） |
|---|---|
| 上述三个 props | 边框、圆角、配色、玻璃质感、阴影 |
| 消息模型 `{id, role, segments, pending?, error?}` | 入场/呼吸动画（但见 §2.2 的降级约束） |
| 发送状态机：空闲 → 发送中（占位气泡）→ 成功替换 / 失败替换为错误气泡 | 图标、字号、间距、响应式断点 |
| `parseMessageSegments` 调用点与三种 segment 的分支渲染 | 按钮长什么样、文案怎么说 |
| `kb` → 回调宿主；`exp` → 新标签打开 | 悬浮窗停靠位置、尺寸 |
| Esc 分层、IME 守卫、自动滚到底 | 是否显示「清空」按钮 |
| 会话状态在组件内、跨开合保留 | — |

**关键解耦点**：组件**不认识**知识库面板。它只调用 `onJumpToKnowledge(target)`，把「怎么跳」交给宿主。因此宿主从「同页面板」换成「独立页面 + URL 参数」时，本组件零改动。

## 2.2 两条结构性约束（不是审美问题，改了就坏）

换皮肤时最容易无意破坏的两件事：

1. **必须挂在被置为 `inert` 的那棵子树之外。** 宿主在打开面板时会给主内容区加 `inert`；悬浮窗若在其内部，面板一开就点不动了——而点协议链接恰恰会打开面板，等于自锁。
2. **层级必须高于全屏面板遮罩。** 跳转后面板会盖上来，若悬浮窗在其之下，用户刚被送到目的地，来源对话就完全消失了。

另有一条降级约束（来自项目规范，换 UI 时同样适用）：**动画只允许 `transform` / `opacity`**，且必须能被「安静模式 / 静态模式」的全局 `animation: none !important` 覆盖。新增任何 `box-shadow`、宽高、`filter` 过渡都会破坏弱机与 `prefers-reduced-motion` 路径。

若全局有 `user-select: none`，对话区要显式恢复 `user-select: text`，否则答案无法复制。

## 2.3 两个交互细节（含踩坑记录）

**Esc 分层**：宿主的面板组件在 `document` 上挂了冒泡阶段的 Esc 监听。悬浮窗要在 `document` 上用**捕获阶段**监听并 `stopPropagation()`，才能实现「一次 Esc 只关最上面一层」。

> ⚠️ **验证陷阱**：用 `document.dispatchEvent(new KeyboardEvent(...))` 造测试事件会得到**相反**的结论。此时事件 target 就是 `document` 本身，捕获/冒泡在同一节点上退化为**按注册顺序**执行，先注册者先跑，看起来像分层失效。真实按键的 target 是聚焦元素，`document` 是祖先，分层才按预期工作。
> **测键盘分层，必须把事件派发进面板内部的元素。**

**中文输入法**：`Enter` 发送必须加 `event.nativeEvent.isComposing` 守卫。否则拼音选词按 Enter 会直接把半截输入发出去——纯英文环境下测不出来。

## 2.4 长列表定位机制（可复用到任何目录/文章/题库页）

这套机制与学科无关，是本项目里最值得复用的一块。契约：

```ts
type KnowledgeTarget = { chapter: string; pointId?: number; query?: string }
```

宿主只要把 `initialTarget` 传进面板，面板负责完成剩下全部事情。五个必要环节：

1. **稳定 DOM 锚点**：每个条目 `id="kb-point-<id>"`，每个分组 `id="kb-chapter-group-<index>"`。命名可换，但**必须可由 target 反推**，且分组 index 要有稳定的来源（从章节数组建 `Map<name, index>`，不要靠 DOM 顺序）。
2. **先保证目标被渲染，再谈滚动**：面板用 `initialTarget.chapter` **预置筛选状态**。若不做这一步，目标条目根本不在 DOM 里，`querySelector` 返回 null，表现为「点了没反应」。这是最容易漏的一环。
3. **两种定位策略**：有 `pointId` → `scrollIntoView({block:"center"})`；只有分组 → 手动算 `offsetTop` 对齐分组头（分组比视口高时 `scrollIntoView` 会把标题滚出屏幕）。
4. **高亮是临时的**：加类 → 定时移除（本项目 2800ms）→ 卸载时清 timer。永久高亮会让用户以为那是个特殊条目。
5. **副作用以 target 对象身份为 key**：`useEffect(..., [initialTarget])`。宿主每次传新对象，即使内容相同也会重放定位——这是特性不是 bug（允许重复点击同一链接重新滚动）。

聚焦时机上，`scrollIntoView` 之后延迟约 90ms 再 `focus({preventScroll:true})`，避免焦点抢占把滚动位置拽回去。

**换一个长列表页要改的只有 5 处**：锚点 id 前缀、分组 index 来源、筛选预置字段名、高亮类名与时长、滚动容器 ref。逻辑骨架照搬。

## 3.2 知识库数据规范

条目形状（字段名可换，语义角色必须有对应）：

```ts
{ id: number;      // 全局唯一、稳定、永不复用 —— 它是 DOM 锚点和协议间接寻址目标
  part: string;    // 大类，用于一级筛选
  chapter: string; // 章名，必须与 chapters[].name 逐字符相等（它是 join key）
  chapterPages: string; // "359-376"，用于页码→章定位
  section: string; // 小节标题，§3.5 的编号匹配从这里抽
  summary: string; // 正文摘要
  terms: string[]; // 检索关键词
  page: number }   // 单页整数，覆盖区间的排序依据
```

四条硬要求：

1. **`chapter` 必须与章节表里的 `name` 完全一致**（含全角冒号、空格）。不一致时筛选会静默返回空列表，不报错。
2. **`page` 必须是单个整数**，不能写 "371-373"，否则排序与覆盖区间全废。
3. **`id` 永不复用**。它出现在 URL 锚点、DOM id、协议跳转结果里；换号会让历史链接指向错条目。
4. **数据块必须是纯 JSON 形态**：双引号键、无注释、无 JS 表达式、无尾逗号。因为**构建脚本会截取这段文本直接 `JSON.parse`**（本项目是 `scripts/build-question-index.mjs`）。写成合法 TS 但非法 JSON（加注释、用单引号）会让索引构建崩掉。这是纯数据文件却藏着构建期耦合的地方，最容易踩。

页码口径要显式声明并集中换算（本项目 `pdfOffset: 28`：阅读器页 = 印刷页 + 28）。协议里的数字必须是**印刷页码**，因为那是书脊上印的、人和模型都看到的数字。

## 3.3 检索索引再生成

若沿用「本地 BM25 类检索、完全离线、不调模型」的问题导向模块，索引必须由脚本从**知识库数据 + 原始 Markdown** 生成：

```
资料库/<学科>/  *.md  ─┐
data/knowledge-base.ts ┴─▶ npm run qa:index ─▶ data/question-index.ts（生成物）
```

规则：运行时只读生成物；改了源必须重跑；**永远不要手改生成物**。换学科时源 Markdown 目录和脚本里的文件名约定要一起换。

## 3.4 实验沙盒挂载规范

当前实验运行时是一份 ES5 IIFE 挂到 `window.LAB`，页面结构固定为：

```html
<link rel="stylesheet" href="lab.css" />
<script src="lab.js"></script>
<script src="exp-e13.js"></script>   <!-- 内部 LAB.register("e13", fn) + 末尾 LAB.boot() -->
```

`LAB` 对外契约（换引擎时保持不变，实验页就能继续复用外壳）：
`register(id, def)`、`boot()`、`fitCanvas()` → `{canvas, redraw, ctx}`、`ui.control/slider/segment/btn`、`metrics.set`。

### ⚠️ 挂 Three.js 会撞上一条现成雷区

项目明文规定：**实验页必须是纯经典 script，能 `file://` 直开，不引入外部 CDN / ES module / fetch**。而 Three.js 的常见用法恰好是 ESM 或 CDN。三条路：

| 方案 | 是否可行 | 说明 |
|---|---|---|
| CDN `<script src="https://…three.min.js">` | ❌ | 断网即废，违反离线要求 |
| ESM `import` + importmap | ❌ | `file://` 下模块加载被 CORS 拦死，双击直接白屏 |
| **把 UMD 构建产物放进 `public/experiments/vendor/three.min.js`** | ✅ 推荐 | 仍是经典 script、仍可离线直开；本地文件不算「外部 CDN」 |

采用第三种时注意：导出脚本的复制过滤器**只按 basename 判断**（排除 `_` 前缀、`tmp-*`、`exps`），所以 `vendor/` 子目录会被自动带到发布副本里，无需改脚本。但单文件体积会明显上涨，且要同步更新那条「不引入外部依赖」的雷区措辞——**明确写成「允许本地 vendor 目录，禁止任何远程 URL」**，否则后续维护者会以为违规。

若新学科的实验需要更重的能力（WebGPU、物理引擎、需要联网的模型推理），那 `file://` 直开这条约束就得**显式重新决策**，而不是悄悄破例。这是架构决策，不是实现细节。

### 新增实验的同步项

1. `data/experiments.ts` 加记录（编号、标题、章节标注、页码、是否课程要求、用途）
2. `public/experiments/` 加 `exp-<id>.html` + `exp-<id>.js`
3. 编号格式要和 §1.6 的 `exp://` 参数规则对齐（本项目用 `E13` ↔ 文件名 `e13`，大小写转换在解析器里做）
4. **固定随机种子**：重置必须复现同一结果。这是教学需求，不是保守——学生讨论时要能对同一条曲线。

## 3.5 让 `exp://` 精准指向新实验页

协议里的编号要能落到文件，靠的是三者的**命名一致性**：

```
云端提示词的合法编号集合  ==  data/experiments.ts 的 code 字段  ==  exp-<id>.html 文件名
```

三者任一脱节，就会出现「按钮能点但 404」或「编号合法但被降级成文本」。链接必须保持**相对路径**（`experiments/exp-e13.html`，不以 `/` 开头），因为静态发布可能被放在子目录下，绝对路径会失效。

条目与实验的关联规则（§1.8-B）换学科后要重新推导：物理里可能是「章节号 + 实验册编号」，化学里可能是「课题号」。但**「用编号匹配而不是页码相等」这条原则不变**，理由见 §1.8。

## 3.6 提示词需要改的地方

换学科时云端要同步动的四处，缺一处就会出现「协议格式对但内容错」：

1. **知识库/参考文档**整体替换为新学科教材切片——这是页码正确性的根源
2. **合法编号集合**：把实验编号表和「章节号 ↔ 页码」对照表**以封闭清单形式**写进系统提示词，并明确禁止引用清单外的值
3. **协议输出规则**：格式模板 + 正反例（见 §4.2）
4. **工作流分支**：若平台侧有强制调用的子工作流（本项目有一个检索工作流），约束必须加在**实际生效的那条分支**上。加在主干但被工作流绕过，是「已经加了约束却仍然出错」的最常见原因

### 本项目实测到的反面教材

问「梯度检查在教材哪一节、有无配套实验」，即使已加约束，模型仍答 `kb://114` / `exp://E10`、`P.127` / `E12`——编号格式完全合规，**值是错的**（正确为 11.5 节 / P.371-373 / E13）。其中 `exp://E10` 被前端降级了（集合里没有），但 `kb://127` 静默跳到了一个真实存在但无关的条目。

结论：**协议格式约束容易生效，取值正确性很难靠提示词保证。** 所以 §1.8 的白名单校验和 §4.1 的回归用例不是可选项。

## 4.2 可直接粘贴的提示词约束模板

```
【输出协议】回答中凡引用教材内容或实操实验，必须以如下格式给出链接：
  [简短标签](kb://印刷页码)
  [简短标签](exp://实验编号)

【取值约束】页码与实验编号只能取自下方清单，禁止推测、禁止自创、禁止四舍五入到邻近页：
  实验编号全集：E04 E08 E11 E12 E13 E21 E22 E27 E32 E33
  页码 ↔ 章节对照：<在此处嵌入完整对照表>
若某个知识点在表中不存在，就不要给链接，改用文字描述，禁止猜一个页码。

【格式约束】方括号与圆括号使用半角；标签内不换行；一条回答中可包含多个链接。

【正例】梯度检查见 [11.5 调试策略](kb://371)，配套实操见 [梯度对拍](exp://E13)。
【反例】[P.373](373) ✗ 缺协议名 · [教材](kb://约373) ✗ 含非数字 · [x](exp://E99) ✗ 编号不在全集
```

最后一行**反例必须保留**：只给正例时，模型会输出 `[教材](knowledge://373)` 这类「结构自洽但协议名错」的变体，前端会静默当纯文本处理，表现为「链接莫名消失」。

## 4.3 反模式速查

| 别做 | 会怎样 |
|---|---|
| 前端直连模型平台 | CORS 拦死；PAT 公开可见 |
| 用 Next API 路由代替独立代理 | 静态导出/`file://` 版本整条 AI 链路失效 |
| 解析器返回 HTML 字符串 | 模型输出可控的 XSS 注入点 |
| `exp://` 不做集合校验 | 生成 404 链接，用户怀疑整个系统 |
| 页码→条目用最近邻 | 跳到语义错误的相邻小节 |
| 条目→实验用页码相等 | 漏挂 + 误挂同时发生 |
| 跳转前不设筛选预置 | 目标不在 DOM，点了没反应 |
| 悬浮窗挂在 `inert` 子树内 | 面板一开就点不动 |
| 手改索引生成物 | 下次重跑全被覆盖 |
| 数据文件写成合法 TS 但非法 JSON | 索引构建期 `JSON.parse` 崩 |
| 用 `document.dispatchEvent` 测键盘分层 | 得到与真实行为相反的结论 |
| 漏 `isComposing` 守卫 | 中文输入法选词时误发送 |
| 只在提示词主干加约束、被工作流分支绕过 | 「明明加了约束却还是错」 |
| 实验里用 `Math.random()` | 学生之间结果对不上，破坏教学可复现性 |

## 4.4 一句话总纲

> **协议、通信、解析、定位四件事是平台无关且学科无关的，做完就别再动；**
> **会变的是数据形状的实现、编号集合、映射规则和视觉。**
> 迁移的成本几乎全部落在数据和云端配置上——如果发现自己要改解析器才能接上新学科，说明数据没按规范准备。
